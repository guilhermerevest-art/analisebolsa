# analisebolsa — Fase 1: plano de implementação

Data: 2026-11-24
Spec: [`../specs/2026-11-24-fase1-fundacao-design.md`](../specs/2026-11-24-fase1-fundacao-design.md)

A Fase 1 é entregue em etapas pequenas, cada uma em um PR que deixa o CI verde.
Cada etapa só depende das anteriores.

## Etapa 1 — Base de dados e ingestão (este PR)

1. **Estrutura do repositório.** `apps/api` como pacote Python gerenciado com `uv`
   (Python 3.12, `ruff`, `pytest`), `docker-compose.yml` para dev local
   (postgres + api), `.env.example`, CI no GitHub Actions.
2. **Schema.** Migration Alembic inicial com as tabelas da seção 3 da spec
   (`ativos`, `cotacoes_diarias`, `indicadores_diarios`, `proventos`,
   `fundamentos`, `execucoes_job`) e as tabelas do Auth.js (`users`, `accounts`,
   `sessions`, `verification_tokens`) já com `password_hash`, `plano` e `role`.
3. **Domínio puro** (`dominio/`): modelos (`Candle`, `Provento`, `AtivoInfo`,
   `Fundamentos`), validação de candles e indicadores em pandas
   (MM, MME, RSI de Wilder, MACD, Bollinger, ATR, média de volume), com testes
   contra valores de referência.
4. **Fontes** (`fontes/`): protocolo `FonteDados`, `YahooFonte`, `BrapiFonte` e
   a cadeia de fontes com retry/backoff para 429 e 5xx. Testes com fixtures JSON,
   sem rede.
5. **Worker** (`worker/`): repositório SQL (upserts idempotentes), orquestração
   do EOD (catálogo, cotações, validação, proventos e ajuste, indicadores,
   fundamentos, revalidação) e backfill retomável. Testes de integração contra
   Postgres real.

## Etapa 2 — API FastAPI

Rotas `/v1` da seção 5, JWT interno HS256 (exp ≤ 60 s), erros RFC 7807,
agregação semanal/mensal em SQL, Dockerfile, healthcheck, testes com
`httpx.AsyncClient`. Exportação do OpenAPI para `packages/api-types`.

## Etapa 3 — Web: esqueleto, auth e BFF

Next.js 15 + Tailwind + shadcn/ui, Drizzle só com tipagem, Auth.js v5
(credenciais com argon2id e Google), `/entrar`, `/cadastro`, `/conta`, BFF
`/api/*` com JWT interno, `/api/internal/revalidate`.

## Etapa 4 — Web: página do ativo e landing

`/ativo/[ticker]` com `lightweight-charts` (candles, volume, overlays, RSI e
MACD), abas de fundamentos e proventos, aviso educacional, busca `Ctrl+K`,
landing com Magic UI, `sitemap.xml`, `/admin`.

## Etapa 5 — Deploy

Mudou em 2026-11-25 de Coolify para Vercel. Dois projetos na Vercel a partir do
mesmo repositório (`apps/web` e `apps/api`, região `gru1`), Postgres gerenciado,
migrations e worker (`0 22 * * 1-5`, backfill sob demanda) no GitHub Actions,
deploy a partir de push na `main`, backfill inicial. Passo a passo em
[`../../deploy.md`](../../deploy.md).
